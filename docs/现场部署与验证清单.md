# Data Relay 现场部署与验证清单

## 交付包选择

- `*-source.zip`：用于现场首次联调和需要 VSCode 断点排查的场景；服务端业务代码可读，激活码核心仍为 JSC。
- `*-jsc.zip`：用于联调完成后的正式运行；服务端业务代码与随包 TCP/UDP 模拟工具均为 JSC。
- 文件名中 `licensed` 为需激活版，`unlicensed` 为免授权版；必须与合同交付类型一致。
- 两种包的配置、数据库和日志目录结构一致。切换包前应先停止服务并备份 `data/`、`.env` 和必要日志，不能同时启动两个包占用同一端口或操作同一数据库。

## 1 部署前检查

- 使用与现场服务器操作系统、CPU 架构完全一致的离线包。
- 核对 `VERSION.json`，并按 `SHA256SUMS.txt` 校验交付文件。
- 确认管理端口、设备接入端口和 FDBServer 端口未被占用；双协议模式要分别检查同一数字端口的 TCP 与 UDP 占用情况。
- 仅向设备所在网段开放所选 TCP/UDP 接入端口，管理端口限制在运维网段。
- 保证 `data`、`logs` 所在磁盘具备约定容量和写权限。

## 2 启动

1. 解压离线包到不含中文、不会被定期清理的固定目录。
2. 按 `FIRST_RUN.txt` 登录管理后台。
3. 授权版在“软件授权”页面复制机器码，由内部生成器按合同设备数和有效期签发激活码并导入；免授权版跳过此步。
4. Windows 右键以管理员身份运行 `install-service.cmd` 注册并启动系统服务；Linux 运行 `start.sh`。
5. 使用 `status.cmd` 确认Windows服务为 `Running`；Linux使用 `status.sh` 确认 `data-relay` 为 `online`。
6. 请求 `/api/health/ready`，确认所选接入模式监听为 `true` 且 `license.valid` 为 `true`；免授权版还应显示 `license.required=false`。
7. Windows重启并保持无人登录，验证服务自动启动；需要取消时以管理员身份运行 `uninstall-service.cmd`，数据和激活保留。

## 3 KH 联调

1. 在转发配置中填写 FDBServer Base URL、用户名、密码和固定 `clientName`。
2. 执行“注册客户端”，记录真实返回。
3. 执行“同步 KH 点位”，核对点位数量和类型。
4. 为一台测试设备配置完整 KH 点位映射，不使用自动拼接点名。
5. 启用 KH 写入，先发送一条当前时间报文，再检查 KH/KS 中的值和时间。
6. 分别验证浮点、累计整数、开关量，以及不存在点位、类型不匹配和鉴权失败。
7. 根据现场返回确认 `khinsert.data.tag_oks` 表示失败点位还是成功点位，并设置 `insertResultMode`。
8. 验证一次 `khinsert` 是否接受同一 `tagName` 携带多个不同 `writeTime`；如果不接受，暂停批量帧投运并由开发人员将 KH 提交策略切换为按采样时刻拆批。
9. 使用现场批量帧核对 A01、A02、P01、P02 共32个历史点及8个采样时间。

## 4 设备协议验证

- 正常单帧。
- `D:030;T:08` 且 A/P 字段使用 `|` 分隔的批量历史帧。
- 批量值数量与 T 不一致、空值、非法数值及跨天时间展开。
- 一条报文拆成多个 TCP 包。
- 一个 TCP 包包含多帧。
- UDP 单数据报单帧、单数据报多帧、超长数据报和不完整数据报。
- 帧前存在无效字节。
- 长连接连续上报与每帧短连接。
- A04、P03、K01 和不同固件字段组合。
- LEN 的实际计算范围。
- 校验值算法及参与计算的字节范围。

LEN 和校验未确认前保持“记录警告”，确认后再切换为“严格拒绝”。

## 5 可靠性验证

- 停止 FDBServer 1 小时，确认 TCP/UDP 报文继续落盘且任务保持待写。
- 恢复 FDBServer，确认队列自动补写且没有重复生成任务。
- 人工结束 Node.js 子进程，确认 PM2 自动拉起。
- 重启服务器，确认计划任务、PM2 和未完成任务自动恢复。
- 断开一台设备超过两倍上报周期，确认后台日志出现未上报记录；恢复上报后出现恢复记录。
- 检查 PM2 日志和业务日志轮转，确认不会无限增长。

## 6 300 设备验证

- 渐进建立300条连接并保持，确认活动连接数达到300、错误数为0。
- 模拟集中重连时，根据目标系统调整 TCP listen backlog。Linux 同步检查 `net.core.somaxconn`。
- 记录进程内存、CPU、磁盘写入和 SQLite WAL 大小。
- KH 停止期间持续收数，确认 TCP/UDP 接入不被 KH 请求阻塞。

## 7 验收记录

现场记录至少包括：软件版本、配置备份、设备数量、点位数量、测试报文、KH 请求与响应摘要、失败恢复结果、300连接测试结果、遗留协议结论和回退步骤。不得记录 KH 密码或完整 Authorization。
