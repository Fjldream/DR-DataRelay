# Windows KH批量帧现场测试步骤

## 1 测试目标

本次验证从 Windows 上的 TCP/UDP 批量帧模拟器到 Data Relay、SQLite 可靠队列、FDBServer REST 接口和 KH 历史数据的完整链路。默认模拟3台设备，每帧包含 A01、A02、P01、P02 四个批量字段，每个字段8个历史样本。

## 2 测试前准备

1. 使用 Windows x64 构建的 v0.3.4 交付包，不要使用 macOS 产物。
2. 确认 Data Relay 、FDBServer 和 KH 时间正确，时区统一为 Asia Shanghai。
3. 准备每台模拟设备对应的独立 KH 点位，不得跨设备复用同一完整点名。
4. 授权版先完成激活；免授权版可直接测试。
5. 转发配置中先保持 KH 写入关闭，接入模式按现场选择“仅 UDP”或“TCP + UDP”，监听 IP 设为 `0.0.0.0`，端口例如 `9000`；保存后重启服务。

LEN 和现场真实校验规则未确认前，保持“记录警告”。本模拟器生成的校验值为 XOR8；如只测试模拟帧，可临时选择 XOR8 并使用严格校验。

## 3 首次发送和设备配置

在 Data Relay 所在 Windows 电脑上双击 `simulate-batch.cmd`。默认参数为：

```text
127.0.0.1 9000 3 5000 60 8 30 true tcp
```

也可在命令行指定参数：

```bat
simulate-batch.cmd 127.0.0.1 9000 3 5000 10 8 30 true udp
```

倒数第二个参数控制是否打印完整原始报文，`true` 表示打印，`false` 表示关闭；最后一个参数选择 `tcp`、`udp` 或 `both`。UDP 报文会以 `[FRAME][UDP][设备编号][STC]` 开头输出；设备数量较多或进行性能测试时建议关闭打印。

也可以直接使用固定入口：`simulate-tcp.cmd`、`simulate-udp.cmd` 或 `simulate-tcp-udp.cmd`。双协议入口会将奇数编号设备分配给 TCP、偶数编号设备分配给 UDP。

首次建议只运行10秒，用于自动发现设备。默认3台设备为：

| 设备 | STC | SN |
| --- | --- | --- |
| 设备1 | 20191001088 | 691001088 |
| 设备2 | 20191001089 | 691001089 |
| 设备3 | 20191001090 | 691001090 |

进入设备管理，为三台设备设置现场可识别的名称，分别配置 A01、A02、P01、P02 的完整 KH 点位。批量字段只配置一次点位，程序会将一帧自动展开为8个写入时间。

## 4 KH 联调

1. 填写 FDBServer Base URL、用户名、密码和 clientName。
2. 依次执行注册客户端、测试连接和同步 KH 点位。
3. 确认三台设备映射保存成功，再启用设备转发和 KH 写入。
4. 重启 Data Relay，然后运行：

```bat
simulate-batch.cmd 127.0.0.1 9000 3 5000 60 8 30 true udp
```

5. 模拟器结束时会输出 `sentFrames`。若每台设备启用四个批量字段，预期 KH 历史点数为 `sentFrames × 4 × 8`。
6. 在 KH 中核对每个点位的数值、时间戳和30分钟间隔。每帧的最后一个样本时间应接近发送时间。

## 5 异常与恢复验证

1. 发送期间短暂停止 FDBServer 或断开网络，确认日志中出现 KH 写入失败，且队列保留。
2. 恢复 FDBServer 或网络，确认队列自动补写，KH 中历史时间仍使用 TM 展开时间，不是恢复时间。
3. 确认日志中没有重复的高频成功日志，仅异常和恢复线索可追溯。

## 6 现场必须记录的结果

- FDBServer 版本、Base URL 和最终使用的端口。
- `khinsert` 是否支持同一 `tagName` 在一次请求中包含多个不同 `writeTime`。
- `tag_oks` 在现场版本表示成功点还是失败点。
- 单批100点的平均响应时间，以及是否存在请求体大小限制。
- 三台设备的帧数、预期点数、KH 实际点数和失败日志。
