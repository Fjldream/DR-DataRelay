# v0.3.4 Windows服务与设备批量删除

## 设备多选删除

设备表格支持逐行勾选和表头“全选当前页”，点击“删除所选”统一确认。翻页、筛选或刷新会清空本页选择，避免隐藏选项被误删。

一批删除在同一事务中执行。如果任一设备有pending/retry/deferred/sending/license_hold任务，整批不删除，并提示阻塞设备名称、STC和待写数量。删除后设备停用并从列表隐藏，历史报文、任务和日志保留。设备继续上报时，会以待配置设备重新出现，需重新启用映射。

## Windows服务操作

1. 将Windows x64离线包解压到固定目录，保留该目录的程序、runtime、node_modules和服务文件。
2. 右键 `install-service.cmd`，选择“以管理员身份运行”。脚本注册并启动 `DataRelay` 服务，显示名称为 `Data Relay`，默认LocalSystem账户、自动启动。
3. 在 `services.msc` 中确认服务存在，再打开管理后台或 `/api/health/ready` 检查应用实际就绪。
4. 之后以管理员身份运行 `start.cmd`、`stop.cmd` 或 `restart.cmd` 启停服务，运行 `status.cmd` 查看状态。
5. 取消注册时，右键以管理员身份运行 `uninstall-service.cmd`。服务停止并移除注册，data、logs、.env和激活文件均保留。取消后仍可通过start.cmd手动启动PM2；无需继续运行时不要执行start.cmd。

注册服务与取消服务都会在控制台保留结果，失败时不会直接闪退。注册后的目录不可直接移动；更换位置前先在旧目录取消注册，迁移数据与配置后再从新目录注册。若同名服务已指向其他目录，脚本报错并拒绝接管。

旧版本计划任务只在确认属于当前目录时自动移除；其他目录的同名计划任务需要先从原目录处理。服务模式与手动PM2共用本包data/pm2；注册前会停止本包旧PM2，避免同时运行两个实例。不要使用全局PM2另外启动同一份工具。

## 离线内容与日志

Windows构建阶段将官方WinSW v2.12.0 x64可执行文件复制成 `DataRelayService.exe`，同时携带 `DataRelayService.xml`、管理脚本和MIT许可；构建时校验固定SHA-256，现场注册无需下载依赖。服务运行链路：Windows服务管理器 → WinSW → PM2前台运行器 → Data Relay单实例。PM2负责应用重启；服务进程退出时由Windows服务恢复策略重启。

WinSW输出位于logs，按10MB大小滚动、保留5份归档；业务日志仍按后台配置保留，默认90天。异常时双击collect-diagnostics.cmd收集日志、服务状态和脱敏报告。

## Windows现场验证

- 在source包和jsc包分别注册、停止、启动、重启、取消注册。
- 注销用户、无人登录重启Windows后，检查服务自动运行及设备继续收报。
- 结束Data Relay应用进程，确认PM2恢复；结束服务管理进程，确认服务恢复。
- KH短时不可用后恢复，核对队列补写；重启服务后未完成任务保留。
- 取消服务注册后确认端口释放且数据和激活文件保留。

当前开发机是macOS，服务资产校验、构建集成和批量删除回归已在本地验证；真正的Windows服务注册、账户权限和无人登录启动需在Windows上完成上述验收。
