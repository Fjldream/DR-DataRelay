# Data Relay v0.3.0 批量历史帧升级与测试报告

## 升级结论

v0.3.0 已兼容原单值帧和现场批量历史帧。现场 `LEN:0431` 样本可解析为 8 个采样时间，A01、A02、P01、P02 共生成 32 条 KH 写入任务。V、V1、CSQ 等单值字段如启用映射，只在 TM 对应时间生成一次任务。

## 主要变更

- 新增 `|` 分隔批量数值解析，并严格校验 D、T、空值、数值格式和最大样本数。
- 使用设备本地墙上时间进行跨小时、跨日、跨月和跨年展开，不依赖服务器时区。
- LEN 自动模式新增现场“从 @ 到校验值前分号”口径，并保留旧单值帧口径。
- SQLite 任务唯一键升级为 `(frame_id, tag_name, write_time)`，增加 `sample_index`；旧数据库启动时事务迁移并保留任务状态。
- 同一原始帧及全部任务在一个事务内落盘；任务冲突不再静默忽略。
- KH Worker 在队列繁忙时连续排空，空闲时才按普通轮询间隔等待，仍保持单请求并发。
- KH 返回失败点位时，同名点位的所有历史时刻保守重试；失败日志按原始帧聚合。
- TCP listen backlog 默认 1024；设备点位映射增加内存缓存；历史清理改为小批次执行。
- 正常成功帧和KH成功批次不写业务日志，重复帧和解析错误进行限频。

## 自动化测试

2026-11-05 使用 Node.js v22.14.0 执行全部测试：34 项通过，0 项失败。覆盖：

- 原单值帧及旧 LEN 口径严格模式回归；
- 现场0431批量帧及32点生成；
- 8个半小时时间展开和跨年展开；
- T不匹配、空值、缺少D、样本超限；
- 同点位多历史时间的SQLite保存、原子回滚及旧数据库迁移；
- KH同点位多时间批量请求和失败重试；
- 未配置设备不保存报文、无映射设备不生成任务；
- KH REST接口请求结构。

- TCP连接：300/300，错误0；
- 报文：发送300、接收300、落盘300；
- 历史点：预期9600、SQLite 9600、KH模拟接收9600；
- KH请求：96批，最终队列为零；
- 总耗时：5.15秒；
- RSS峰值：90.49MiB；
- 堆峰值：14MiB；
- 事件循环P99：29.77ms，最大62.32ms；
- SQLite与WAL：8.6MiB。
