# 异常报文日志增量补丁

补丁版本以同目录 PATCH.json 的 patchVersion 为准。适用于 0.3.4、0.3.5 的 source 交付版（运行 src/index.js），Node 22；不适用于全 JSC 版。只替换平台无关的 JS/CSS，不需要重装、安装依赖、重新注册服务或迁移数据库。

## 文件清单

- overlay/src/tcp/server.js → 程序目录/src/tcp/server.js
- overlay/public/app.js → 程序目录/public/app.js
- overlay/public/responsive.css → 程序目录/public/responsive.css

三份文件已压缩。不要把整个 src 或 public 目录删除后替换，应该合并目录并覆盖上面三个文件。不要覆盖 data、logs、.env、runtime、node_modules、授权文件或已有服务注册配置。补丁保留现场原包版本元数据，以 PATCH.json 单独记录增量版本，不能据此宣称现场整包已升级为同版本。

## 操作步骤

1. 确认正在运行的程序目录。不要选择 windows-build-source 源码构建目录，应选择里面实际运行的 releases/data-relay-...-source 目录。可在 PowerShell 执行下面的只读命令，查看 8080 对应进程的完整 CommandLine；若前端端口改过，替换 8080。**以 CommandLine 中 src/index.js 所在目录为准，不能只看 node.exe 路径。** 若发现仍启动旧目录，先修正正在运行的目录再应用补丁。

   ```powershell
   Get-NetTCPConnection -LocalPort 8080 -State Listen |
     Select-Object -ExpandProperty OwningProcess -Unique |
     ForEach-Object {
       Get-CimInstance Win32_Process -Filter "ProcessId=$_" |
         Format-List ProcessId, ExecutablePath, CommandLine
     }
   ```

2. 在该程序目录打开管理员 PowerShell，执行 `.\stop.cmd`。确认停止成功且端口不再监听；若失败不要继续替换。停机期间设备上报可能丢失，尤其 UDP 不会自动补发，请安排短暂停机窗口。
3. 把原来的三个文件备份到程序目录之外，保留各自路径。然后把本补丁 overlay 中的 src、public **合并覆盖**到该程序目录，只替换清单中的三个文件。可把 PATCH.json 另存为程序根目录 `diagnostic-PATCH.json` 留档。
4. 执行 `.\start.cmd` 启动原来的服务。在浏览器按 **Ctrl+F5** 强制刷新，重新登录。
5. 让现场设备重新发送一次。进入“日志查询”，点击对应异常日志下面的“查看详情”。新的异常记录将显示接收字节数、文本、十六进制、来源和预览是否截断。旧日志没有记录过的原文无法恢复。

## 校验与回退

PATCH.json 的 files 包含三个替换文件的 SHA-256。在程序目录使用 `Get-FileHash .\src\tcp\server.js -Algorithm SHA256` 等命令核对。重新运行上面的进程命令，确认确实从被替换目录启动。

如需回退：停止原服务，恢复备份的三个文件，启动并强制刷新浏览器。数据库与授权无需回退。

## 记录范围与限制

- 仅在异常时记录，正常报文不会逐条写日志；预览计算发生在日志限频通过之后。
- 文本与十六进制对应前 1024 字节，超过会明确标记截断；十六进制可辨别换行、空字节及其他不可见内容。
- UDP 未完成、超长和前缀异常，TCP 缓冲异常、关闭时残留，以及完整报文解析失败均包含预览。TCP 缓冲异常预览是本次接收片段，并不保证覆盖历史累计的全部数据；详情会标记范围。
- 继续沿用同来源同类异常约 5 分钟限频，以及全局每分钟最多 120 条异常日志和现有保留策略。日志高峰受全局限制，不能保证每一个数据包都有记录。
- 本补丁增加排查能力，不改变协议接受条件、不自动跨 UDP 数据报拼接、不修复设备发来的缺帧内容。
- JS/CSS 不含原生依赖；本机回归验证与现场 Windows 服务运行验证分别看待。更换后仍需在现场核对日志和收报。
