# 现场存库只读排查

在实际运行的 Data Relay 目录中打开 PowerShell，该目录应包含 runtime/node.exe、data/data-relay.db 和 start.cmd。不能只根据 node.exe 路径判断程序目录，应核对运行进程 CommandLine 中的应用入口。以下命令不需要停服务，也不会请求 KH 或修改本地数据库。

## 不拷文件，检查所有设备

如果 PowerShell 仍显示续行提示符 `>>`，先按 Ctrl+C。一次复制下方完整三行执行；没有 here-string 和反引号，不依赖多行字符串结束标记。

```powershell
$sql = 'WITH recent AS (SELECT device_id,COUNT(*) AS tasks,SUM(status=?) AS ok,SUM(status IN (?,?)) AS retry,SUM(status IN (?,?)) AS waiting,SUM(status=?) AS held FROM delivery_tasks WHERE created_at>=? GROUP BY device_id), maps AS (SELECT device_id,COUNT(*) AS points FROM field_mappings WHERE enabled=1 AND length(kh_tag_name)>0 GROUP BY device_id) SELECT d.stc,d.enabled,COALESCE(m.points,0) AS points,d.last_seen_at AS last_rx,COALESCE(r.tasks,0) AS tasks,COALESCE(r.ok,0) AS ok,COALESCE(r.retry,0) AS retry,COALESCE(r.waiting,0) AS waiting,COALESCE(r.held,0) AS held FROM devices d LEFT JOIN recent r ON r.device_id=d.id LEFT JOIN maps m ON m.device_id=d.id WHERE d.removed_at IS NULL ORDER BY d.last_seen_at DESC'
$js = "let db;try{const D=require('better-sqlite3');db=new D('./data/data-relay.db',{readonly:true,fileMustExist:true});db.pragma('busy_timeout=5000');db.exec('BEGIN');const since=new Date(Date.now()-24*3600000).toISOString();const settings=JSON.parse(db.prepare('SELECT value FROM settings WHERE key=?').get('app').value);console.log('KH writing enabled:',!!settings.kh.enabled);console.log('Recent 24h NEW tasks since:',since);console.table(db.prepare(process.argv[1]).all('succeeded','retry','deferred','pending','sending','license_hold',since));console.log('ALL unfinished tasks, including older backlog:');console.table(db.prepare('SELECT status,COUNT(*) AS count FROM delivery_tasks WHERE status<>? GROUP BY status').all('succeeded'));console.log('Recent 24h task failures (latest 20):');console.table(db.prepare('SELECT d.stc,t.tag_name,t.write_time,t.status,t.attempts,substr(t.last_error,1,240) AS reason FROM delivery_tasks t LEFT JOIN devices d ON d.id=t.device_id WHERE t.last_error IS NOT NULL AND t.updated_at>=? ORDER BY t.updated_at DESC LIMIT 20').all(since));}catch(e){console.error('ERROR:',e.message);process.exitCode=1;}finally{if(db)db.close();}"
& .\runtime\node.exe --input-type=commonjs -e $js $sql
```

第一行输出 `KH writing enabled`，false 表示全局 KH 写入关闭。随后三个表分别是全部未删除设备的最近 24 小时新增任务统计、所有历史未完成任务汇总，以及最近 24 小时更新过且仍有错误的最新 20 条任务。时间窗口按任务创建/更新时间计算，不按报文 TM 采样时间计算。

| 列 | 含义 |
| --- | --- |
| stc | 设备站号 |
| enabled | 是否启用设备转发 |
| points | 已启用且填写了 KH 点名的映射数量 |
| last_rx | 最近成功解析并登记设备的接收时间，不等于最后收到任意 UDP 数据的时间 |
| tasks | 最近 24 小时新增写入任务数 |
| ok | 按 KH 接口响应判定成功的任务数 |
| retry | 最近新增任务中处于 retry/deferred 的数量 |
| waiting | 最近新增任务中处于 pending/sending 的数量 |
| held | 最近新增任务中处于 license_hold 的数量 |

带 Z 的时间为 UTC，北京时间需加 8 小时。某设备没有任务不代表存库正常，仍需核对报文是否完整、设备是否启用、字段是否映射并勾选写入、授权是否有效。未配置设备的原始报文不会保留补写。

`succeeded` / `ok` 只是程序按接口响应判定成功。判断实际写入 KH，必须到正确 KH 实例、完整点名和报文 TM 展开的时间范围进行历史回读。不能用实时值或没有异常日志证明历史数据已入库。

## 单设备脚本

`packaging/query-kh-result.cmd` 是针对示例站号 20190320077 和 test111/test112 的临时排查入口。交付包构建时复制到程序根目录，查询最近 50 条任务并暂停窗口；手动使用时也需放在程序根目录。不要把它误认为全设备通用检查。

## 验证边界

查询逻辑已在本机临时数据库验证多设备汇总、旧任务积压、失败原因、无配置密码输出和只读行为。Windows CMD/PowerShell 的实际执行仍需现场确认。较大的历史任务表可能需要等待查询完成；只读聚合仍会产生磁盘读取，避免多次并行执行。
