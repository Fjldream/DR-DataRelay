# Data Relay v0.3.4 全量测试报告

## 1 测试结论

Data Relay v0.3.2 已通过本地自动化测试、TCP/UDP 批量帧模拟器进程测试、TCP 与 UDP 同端口双协议测试、300设备单帧稳态测试、300设备批量帧持续压力测试、300设备瞬时 TCP 连接恢复测试和300设备 UDP 批量帧测试。协议解析、批量历史时间展开、SQLite 可靠队列、批量写入调度和模拟 KH 返回处理均未出现数据数量不一致。

本地测试不能替代现场 FDBServer 和 KH 验证。Windows 现场仍需确认真实 REST 接口鉴权、同一点位多时间戳批量写入、`tag_oks` 返回语义、请求体限制和 KH 中的最终历史点数量。

### 4.3 300设备瞬时连接恢复

300个客户端在无爬坡间隔的情况下同时连接。受本机 TCP accept 队列瞬时容量影响，首次建立连接出现210次短暂重试；模拟器自动重连后300条连接全部成功。稳定连接后运行期 Socket 错误为0，600帧和19200个历史点全部完成处理，最大 RSS 为97.07 MiB。

这说明兼容的 TCP 模式容量满足300设备，但设备大规模同时重启时，TCP 客户端必须具备断线重连能力。客户当前统一使用 UDP，因此该项作为 TCP 备用接入能力验证。

## 5 批量帧模拟器验证

新增 `tools/tcp-batch-simulator.js`，Windows 包提供 `simulate-batch.cmd`。默认模拟3台设备，分别使用 STC 20191001088、20191001089、20191001090；每5秒发送一帧，每帧包含8个历史样本，样本间隔30分钟。

模拟帧字段顺序与现场样例一致，包含 STC、SN、IMEI、CCID、TM、CSQ、V、V1、D、T、C、A01、A02、P01、P02。LEN 动态计算，校验值使用 XOR8。最后一个参数可选择 `tcp` 或 `udp`；TCP 使用长连接、操作系统 Keepalive 和断线后2秒重连，UDP 使用每台设备独立的数据报 Socket。默认在控制台打印每条完整原始报文，倒数第二个参数设为 `false` 时可关闭打印。

## 6 未完成的现场验证

下列项目必须在 Windows 和客户 KH 环境完成：

1. FDBServer Base URL、账号密码和 clientName 的真实鉴权。
2. `khinsert` 是否允许同一 `tagName` 在一个请求中写入多个不同 `writeTime`。
3. 现场版本 `tag_oks` 表示成功点还是失败点。
4. KH 单批点数、请求体大小上限和真实响应时间。
5. 断网或停止 FDBServer 后队列保留，恢复后按原历史时间补写。
6. KH 中实际点数等于模拟器 `sentFrames × 已启用批量字段数 × 8`。
7. 现场真实报文的校验算法。当前模拟器使用 XOR8，LEN 和校验策略在确认前应保持记录警告。

## 7 交付建议

先用 `simulate-batch.cmd` 运行10秒完成三台设备发现和点位映射，保持 KH 写入关闭；映射确认后启用 KH，运行60秒并核对 KH 实际点数和时间戳。通过后再进行 FDBServer 中断和恢复补写测试。详细步骤见《Windows KH批量帧现场测试步骤》。
