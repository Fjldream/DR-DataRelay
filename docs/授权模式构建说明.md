# Data Relay 授权模式构建说明

## 1. 构建开关

编辑 `packaging/build-variants.json` 顶层的 `licenseRequired`：

```json
{
  "licenseRequired": true
}
```

- `true`：授权版。必须导入与服务器机器码绑定的有效激活码，并按激活码限制设备数量和有效期。
- `false`：免授权版。无需机器码、激活码或有效期，设备数量不限制。

必须使用 JSON 布尔值，不能写成字符串 `"true"` 或 `"false"`。配置缺失或类型错误时构建会立即失败。

## 2. Windows 构建

在 Windows x64 构建电脑上设置开关后，双击 `build-windows.cmd`。每次同时生成源码调试包和 JSC 保护包：

- 授权版：`data-relay-<版本>-win32-x64-licensed-source.zip` 和 `...-licensed-jsc.zip`
- 免授权版：`data-relay-<版本>-win32-x64-unlicensed-source.zip` 和 `...-unlicensed-jsc.zip`

`VERSION.json` 同时写入 `licenseRequired` 和 `licenseMode`，可用于交付前复核。文件名和 `VERSION.json` 不一致时不应交付。

## 3. 行为边界

- 该开关是构建参数，不是运行配置；交付后不能通过 `.env` 或管理页修改。
- 免授权包不包含授权公钥，前端隐藏“软件授权”菜单，激活接口会拒绝导入。
- 免授权版首次启动会将同一数据库中的 `license_hold` 任务恢复为待写入，不会丢弃历史队列。
- 从免授权版换回授权版时，如果没有有效激活码，KH 写入会暂停，已有数据和任务保留。

## 4. 交付建议

- 现场联调需要 VSCode 断点时使用 `source` 包。
- 正式运行优先使用 `jsc` 包；授权版不建议长期部署源码包。
- 每次切换授权模式后必须重新构建，不得直接改交付 ZIP 内的文件。
