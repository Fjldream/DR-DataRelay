# TCP/UDP 接入升级说明

## 接入模式

管理后台“转发配置 → 设备接入”支持三种模式：

- 仅 TCP：保持原有 TCP Server 行为。
- 仅 UDP：按 UDP 数据报接收设备帧，不建立或维护连接。
- TCP + UDP：在同一个监听 IP 和数字端口上同时启用 TCP 与 UDP。两种传输协议的端口空间相互独立，不会冲突。

配置保存后需要重启 Data Relay。已有安装升级后如果尚未选择模式，将继续使用“仅 TCP”，避免升级自动改变现场接入方式。

## UDP 处理规则

- 每个 UDP 数据报可包含一条或多条完整的 `@...#` 帧。
- UDP 不支持跨数据报拼接半帧；数据报中的不完整帧会丢弃并记录限频异常日志。
- 超过“最大报文字节”的数据报直接丢弃，防止异常流量占用内存。
- TCP 与 UDP 共用协议解析、设备识别、字段映射、重复帧去重、SQLite 可靠队列和 KH 写入链路。
- UDP 没有连接与断开事件。设备离线仍根据设备配置的“上报周期”，在超过两倍周期未收到报文时判断。
- 页面中的“UDP 活跃来源”是最近一小时内发送过数据报的来源地址与端口数量，不等同于已配置设备数量。

## 现场 UDP 测试

选择“仅 UDP”或“TCP + UDP”，监听 IP 使用 `0.0.0.0`，端口使用现场设备目标端口，保存后重启服务。Windows 交付包执行：

```bat
simulate-batch.cmd 127.0.0.1 9000 3 5000 60 10 30 true udp
```

交付包还提供三个一键入口：

- `simulate-tcp.cmd`：全部模拟设备通过 TCP 上报。
- `simulate-udp.cmd`：全部模拟设备通过 UDP 上报。
- `simulate-tcp-udp.cmd`：奇数编号设备走 TCP、偶数编号设备走 UDP，STC 不重复。

参数中的 `5000` 是每台模拟设备每 5 秒发送一帧，`10` 是每个批量字段的样本数，`30` 是帧内相邻历史样本的分钟间隔，三者相互独立。运行秒数设置为 `0` 时持续发送，按 `Ctrl+C` 停止。

## 诊断日志

默认保留近90天，可在“转发配置 → 日志管理”设置1到3650天。数据库按保留期分批清理；文件达到20MB检查阈值或运行满一天时轮转，定时检查后清理过期归档，因此并非严格20MB硬上限。清理只影响历史日志，不删除尚未完成的KH任务。

同一设备协议警告、同来源解析错误等按5分钟限频；同类KH失败按1分钟聚合。业务日志再设全局每分钟120条上限，超出条数在下一次日志窗口汇总。频繁异常仍会保存相关原始帧和任务状态供进一步检查，日志是故障摘要，不是每帧成功审计流水。

系统只持久化警告和错误，正常收报与成功写入不会逐条记录。管理后台可按级别和分类查询；业务日志保存在 `logs/application.ndjson`，PM2 输出保存在 `logs/pm2-out.log` 和 `logs/pm2-error.log`。日志覆盖接入服务异常、UDP丢弃、协议解析失败、设备未配置/超时/恢复、KH失败/重试/恢复、授权异常及进程未捕获错误。

现场可双击 `collect-diagnostics.cmd` 生成诊断 ZIP。该包不包含 `.env`、KH密码、授权文件、私钥和数据库，但解析失败日志会保留帧的前500字符以便定位格式问题。
